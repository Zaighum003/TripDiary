1. Application Overview
TripDiary is a personal travel journalling mobile application built with Flutter SDK and Dart. It allows users to create trip records, attach photos, voice notes, and location data to diary entries, receive trip reminders, and share memories. The app operates entirely offline using local SQLite storage.

2. Architectural Pattern: MVVM + Repository
2.1 Why MVVM?
MVVM (Model-View-ViewModel) was selected because:
• It enforces a clean separation between UI and business logic
• ViewModels are easily unit-testable without the UI layer
• Provider (state management) integrates naturally as the binding layer
• It differs from the MVP pattern commonly taught in class

2.2 Layer Breakdown

LayerResponsibilityFlutter ImplementationViewUI widgets only, no business logicScreens & reusable WidgetsViewModelExposes state, handles user actions, calls repositoryChangeNotifier classes via ProviderRepositoryAbstracts data source, single source of truthTripRepository, EntryRepositoryData SourceActual database operationsSQLite via sqflite packageModelPure data classesTrip, Entry, Location Dart classes

4. State Management
4.1 Strategy
The app uses the Provider package which implements the Observer pattern. Two types of state are managed:

State TypeDefinitionExample in TripDiaryEphemeral StateLives within a single widget, not sharedForm field inputs, loading spinners, tab indexApp StateShared across widgets, persists in ViewModelList of trips, current user, selected entry
4.2 Provider Setup (main.dart)
void main() {
  runApp(
    MultiProvider(
      providers: [
        ChangeNotifierProvider(create: (_) => AuthViewModel()),
        ChangeNotifierProvider(create: (_) => TripViewModel(TripRepository())),
        ChangeNotifierProvider(create: (_) => EntryViewModel(EntryRepository())),
      ],
      child: const TripDiaryApp(),
    ),
  );
}

5.3 CRUD Operations
Each repository implements the full Create-Read-Update-Delete lifecycle:
• CREATE: insert(trip) - inserts new record, returns generated id
• READ: getAll() - returns List<Trip>, getById(id) - single record
• UPDATE: update(trip) - updates all fields by primary key
• DELETE: delete(id) - removes record by primary key
